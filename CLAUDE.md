# CLAUDE.md — Project context for Claude Code

## What is this project?

isère is a serverless platform for microcontrollers. It runs JavaScript handlers (AWS Lambda-style) on a Raspberry Pi Pico 2 (RP2350, Cortex-M33) via USB Ethernet.

The project was migrated from a C codebase (FreeRTOS + lwIP + TinyUSB) to **Zephyr RTOS + Rust** with QuickJS linked as a C library via FFI.

## Tech stack

- **Zephyr RTOS** — kernel, USB CDC-ECM ethernet, networking, DHCP server
- **Rust** (`#![no_std]`, staticlib) — application logic: HTTP server, event loop, JS runtime wrapper, platform abstraction
- **QuickJS** (C, git submodule at `c_libs/quickjs/`) — JavaScript engine, accessed through raw FFI bindings
- **Target hardware** — Raspberry Pi Pico 2 (RP2350, Cortex-M33, 520KB SRAM)
- **Build system** — west + CMake (Zephyr) invoking Cargo (Rust)

## Build commands

```sh
west build -b rpi_pico2/rp2350a/m33     # hardware build
west build -b native_sim                  # development build (no hardware)
west flash                                # flash to device
```

## Project structure

```
CMakeLists.txt       — Zephyr top-level build (calls rust_cargo_application() + adds c_libs/)
Cargo.toml           — Rust crate (staticlib, no_std)
prj.conf             — Zephyr Kconfig (shared settings)
west.yml             — West manifest (Zephyr SDK, zephyr-lang-rust module)
boards/              — Per-board Kconfig (.conf) and devicetree overlays (.overlay)
c_libs/
  quickjs/           — git submodule (github.com/bellard/quickjs)
  quickjs_shim.c     — C wrappers for QuickJS static inline functions (JS_FreeValue, JS_DupValue, etc.)
  CMakeLists.txt     — Builds QuickJS as a Zephyr library
js/
  handler.js         — JavaScript handler source (ES module with async/await)
  handler.bin        — Pre-compiled bytecode placeholder (generated by scripts/)
scripts/
  compile_bytecode.c — Host tool: compiles JS → QuickJS bytecode
  compile_bytecode.sh — Builds the compiler for 32-bit and runs it
src/
  lib.rs             — Entry point (rust_main), server socket setup, connection state machine, event loop
  httpd.rs           — HTTP/1.1 request parser (zero-copy, no_std) and response builder
  http_handler.rs    — Bridges HTTP request → JsContext → HTTP response
  event_loop.rs      — Poll-based I/O (replaces libuv subset from C version)
  js/
    quickjs_ffi.rs   — Manual FFI bindings to QuickJS C API (~240 lines)
    context.rs       — JsContext: runtime/context lifecycle, custom allocator (k_malloc), handler eval, promise polling
    polyfills.rs     — setTimeout/clearTimeout using cooperative timer polling with k_uptime_get()
  platform/
    tcp.rs           — Zephyr POSIX socket wrapper (socket, bind, listen, accept, recv, send, poll)
    loader.rs        — Handler loading: raw JS source (default) or pre-compiled bytecode (feature = "bytecode")
    logger.rs        — Logging via Zephyr printk
    rtc.rs           — Monotonic clock via k_uptime_get()
```

## Key architectural decisions

1. **Hybrid C + Rust**: Zephyr initializes in C (`main.c` is implicit), then calls `rust_main()`. QuickJS is compiled as a Zephyr C library and linked. Rust accesses it via FFI.

2. **Per-request JS context**: Each HTTP request creates a fresh QuickJS runtime + context. This prevents memory leaks between requests (same pattern as the original C version).

3. **Static inline FFI shims**: QuickJS defines `JS_FreeValue`, `JS_DupValue`, `JS_NewInt32`, `JS_NewBool` as static inline in `quickjs.h`. These can't be linked from Rust, so `c_libs/quickjs_shim.c` provides non-inline wrappers with `isere_` prefix. The Rust FFI uses `#[link_name = "isere_JS_FreeValue"]` to map them transparently.

4. **Cooperative timers**: setTimeout/clearTimeout use a poll-based model (not OS timers). `TimerState` tracks expiry timestamps and fires callbacks during the JS poll loop. A global `TIMER_STATE` pointer is set before eval (safe because single-threaded).

5. **Bytecode compilation**: JS handlers can be pre-compiled to QuickJS bytecode on the host (`scripts/compile_bytecode.sh`), skipping the parser at runtime. The compiler must be built for 32-bit (`-m32`) to match RP2350's pointer size. Enabled via `--features bytecode` in Cargo.

6. **Board-specific networking**: `prj.conf` has shared settings. Networking config is in `boards/*.conf` — Pico 2 uses USB CDC-ECM with DHCP server, native_sim uses TAP interface.

## Important notes

- The `zephyr` crate dependency in Cargo.toml comes from the `zephyr-lang-rust` module (declared in `west.yml`)
- QuickJS bytecode is NOT portable across pointer sizes — always compile with `-m32` for the 32-bit RP2350
- The HTTP server uses Connection: close (no keep-alive) — each request is a full TCP connection
- Max 12 simultaneous connections, 8 setTimeout timers, 2KB request buffer, 4KB response body
- Handler JS format: `export const handler = async function(event, context, done) { return { statusCode, headers, body } }`
